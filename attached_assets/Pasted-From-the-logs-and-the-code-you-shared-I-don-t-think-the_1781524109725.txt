Real fix

For Android 11+ NEVER play from SAF.

Copy video first.

Your comments already say this:

The reliable path is to ALWAYS pre-copy content:// VIDEO sources
into the cache directory

But the implementation doesn't do it.

Instead of:

setDisplayUri(initialSource);

use:

if (
  item.type === 'video' &&
  initialSource.startsWith('content://')
) {
   const cached = await prepareStatusForViewing(
      item as StatusItem,
      { forShare: true }
   );

   setDisplayUri(cached);
} else {
   setDisplayUri(initialSource);
}

before ExoPlayer ever sees the URI.

Second issue

I also see this:

player.replaceAsync(null)

whenever item becomes inactive.

Then:

player.replaceAsync(displayUri)

when active again.

On Android 11 this is expensive.

Every swipe:

release codec
allocate codec
release codec
allocate codec

Many Android 11 devices only have:

1-2 hardware H264 decoders

available.

Codec churn causes freezes.

Better approach

Keep only one player.

Instead of:

ViewerItem -> useVideoPlayer()

for every cell,

use:

ViewerScreen
   single player

and move source between pages.

Instagram, WhatsApp, Facebook Reels and TikTok all do this.

They do NOT create players per item.

Third issue

I see:

nativeControls={true}

<VideoView />

Android 11 + Expo Video has several issues with native controls.

Try:

nativeControls={false}

You already built custom controls.

So native controls are unnecessary.

Fourth issue

Your stall detector threshold is very aggressive:

1500 ms

Many Android devices pause decode for:

300-1200 ms

while refilling buffers.

I would increase to:

4000 ms

for testing.

My recommendation:

Force cache-copy every video on Android 11+.
Feed only file:// URIs to ExoPlayer.
Disable the stall watchdog temporarily.
Disable nativeControls.
Use a single shared player instead of one per ViewerItem.

Those five changes will likely eliminate 90% of the freezes you're seeing.
