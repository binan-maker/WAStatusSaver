Why Android 11+ Amplifies It
2-3 taps needed to open
Inline onPress={() => fn(item)} creates new function identity every render → React.memo on MediaCard breaks → every thumbnail re-renders mid-touch → Android drops the touch event.
SAF state changes trigger frequent parent re-renders. More renders = more dropped touches.
Delay after tap before viewer opens
prepareStatusForViewing runs synchronously before navigation. If it falls back to copyAsync, it blocks the JS thread for 500ms-2s. Router waits for JS thread to clear.
SAF IPC copy is slow. Blocking navigation = perceived app freeze.
Black screen after swiping ~3 images
FlashList/ScrollView unmounts offscreen items (removeClippedSubviews). expo-image releases bitmaps. Swiping back remounts component → re-opens ContentResolver → decodes from scratch → black void until decode finishes.
Android 11+ doesn't cache content:// streams. Every mount = fresh IPC + decode.
Video stuck on thumbnail, no controls
expo-av fails to play content:// SAF URIs directly without explicit flags. Missing useNativeControls or container height 0 hides UI. Player errors silently, leaving thumbnail.
ExoPlayer requires FLAG_GRANT_READ_URI_PERMISSION. SAF doesn't auto-grant it per playback session.
Global scroll/nav stutter (home/saved/settings)
Concurrent heavy I/O (AsyncStorage, SAF reads, ad init, thumbnail queues) starves the main thread. FlashList drawDistance too high → excessive offscreen decoding. Context state updates cascade re-renders.
Android 11+ SAF IPC is synchronous on the native side. Multiple parallel calls block the bridge.
