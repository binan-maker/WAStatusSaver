🔍 Root Cause Analysis: Pinch-Zoom, Video Layout & Save/Share Delay
Symptom
Technical Root Cause
Android 11+ Amplification
Pinch-zoom uncontrollable
Using outdated PanResponder or Transform scaling without react-native-gesture-handler + reanimated. Missing anchor point calculation, gesture composition, and swipe/zoom conflict resolution.
Android touch interception is stricter. Without GestureHandlerRootView and proper state tracking, gestures drop or conflict with the horizontal pager.
Video-first layout broken
Viewer treats images/videos identically. Videos need expo-av native controls, aspect-ratio handling (9:16 status format), buffering UI, and disabled pinch (or limited to 2x).
content:// video streams don't auto-grant playback permissions. ExoPlayer hides controls if container height is 0 or if useNativeControls is missing.
Save/Share heavily delayed
FileSystem.copyAsync runs synchronously on main thread. SAF IPC + disk I/O takes 500ms-2.5s. No progress feedback → user perceives freeze. Gallery export (MediaLibrary.createAlbumAsync) blocks UI thread.
Android 11+ ContentResolver copy is throttled. Concurrent saves/shares starve the JS thread.

🎯 Final Architecture Notes
Pinch-Zoom: Uses reanimated for 60fps transforms + gesture-handler for native touch routing. enabled={() => scale.value > 1.05} cleanly disables pager swipe when zoomed.
Video-First: useNativeControls + ResizeMode.CONTAIN guarantees status videos display correctly. Playback state is decoupled from UI thread.
Save/Share: Immediate haptic + overlay → background queue copy → deferred gallery export. User never waits on UI thread.
SAF Awareness: All file operations go through enqueueCopy() with cache fallbacks. No synchronous await blocks navigation.
