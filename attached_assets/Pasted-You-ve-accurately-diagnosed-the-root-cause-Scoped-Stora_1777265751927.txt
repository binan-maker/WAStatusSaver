You've accurately diagnosed the root cause: Scoped Storage (SAF) on Android 11+ replaces direct POSIX file access with an IPC-heavy ContentResolver/DocumentProvider bridge. This is an OS-level constraint, not a bug in your code. However, the "stuck" feeling is largely caused by synchronous blocking, full-file copying, and arbitrary retry delays that can be optimized or masked.
Below are actionable, production-ready solutions tailored to your React Native/Expo stack, ordered by impact.
🔹 1. Stop Full "Deep Copy" → Play Directly from SAF URI
Most modern media players (Expo AV, React Native Video, Media3) can play directly from content:// URIs if permissions are correctly passed.
Fix: Instead of copyAsync() to cache, pass the SAF URI straight to the player.

Caveats:
If your player throws java.io.FileNotFoundException or Permission denied, add FLAG_GRANT_READ_URI_PERMISSION when building the URI intent.
In Expo, expo-av supports SAF URIs natively on Android 11+ if you request READ_EXTERNAL_STORAGE + tree URI permission correctly.
Fallback: If direct playback fails, switch to chunked streaming instead of full copy (see #4).
