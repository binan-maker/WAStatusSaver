# 🚨 Root Problem (simple version)



On Android 11+:



* You are feeding ExoPlayer a `content://` SAF URI (WhatsApp / Files picker)

* SAF is **slow for streaming**

* First 1 second plays (buffer loads)

* Then buffer refills fail → freeze → error handler triggers



So the real problem is:



> ❌ You are trying to STREAM SAF files instead of converting them into local files first



---



# ✅ Correct Fix Strategy (IMPORTANT)



## ✔️ Rule 1 — NEVER play SAF URI directly



ExoPlayer should only receive:



```

file://local_cache_path.mp4

```



NOT:



```

content://com.android.externalstorage/...

```

# 🔧 FIX ARCHITECTURE (Best solution)



## STEP 1 — Always force copy BEFORE opening player



When user clicks video:



### Do this flow:



```

User taps video

    ↓

    ↓

WAIT until copy finishes

    ↓

ONLY THEN open ExoPlayer with file:// path

```

## STEP 2 — Remove “1-second watchdog”



This is too aggressive and causes false failures.



Replace:



```js

```



With:



```js

```



Better:



> Don't fail based on time. Fail only if ExoPlayer reports real error.



---



## STEP 3 — Fix copy method (MOST IMPORTANT)



Use **FileSystem copy (async await guaranteed)**



### React Native (Expo / bare):



```ts

import * as FileSystem from 'expo-file-system';



async function copyToCache(uri: string) {

  const fileName = uri.split('/').pop();

  const dest = FileSystem.cacheDirectory + fileName;



  await FileSystem.copyAsync({

    from: uri,

    to: dest,

  });



  return dest;

}

```



---



## STEP 4 — Open player ONLY after copy resolves



```ts

const openVideo = async (uri) => {

  try {

    setLoading(true);



    const localPath = await copyToCache(uri);



    setVideoUri(localPath); // file://



    setLoading(false);

    setVisible(true);



  } catch (e) {

    setLoading(false);

    setError(true);

  }

};

```
