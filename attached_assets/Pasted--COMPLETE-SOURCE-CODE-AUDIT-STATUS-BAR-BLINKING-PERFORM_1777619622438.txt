## 🚨 **ISSUE #1: STATUS BAR HIDING (Edge-to-Edge Conflict)**

### **Root Cause Analysis**

Your logs show:
```log
WARN  `setBackgroundColorAsync` is not supported with edge-to-edge enabled.
WARN  `setBehaviorAsync` is not supported with edge-to-edge enabled.
```

**What's happening:**
1. Expo Router enables **edge-to-edge mode** by default on Android 10+
2. Your code calls `StatusBar.setBackgroundColorAsync()` or `setBehaviorAsync()`
3. These APIs **conflict** with edge-to-edge → status bar visibility becomes unstable
4. Result: Status bar flickers/hides when scrolling or navigating

### **✅ EXACT FIX: Force Stable Status Bar**

**Step 1: Disable edge-to-edge in `app.json`**
```json
{
  "expo": {
    "android": {
      "edgeToEdgeEnabled": false,
      "StatusBar": {
        "backgroundColor": "#000000",
        "barStyle": "light-content",
        "translucent": false
      }
    }
  }
}
```

**Step 2: Create a global status bar manager**
Create `src/hooks/useStableStatusBar.ts`:
```typescript
import { useEffect } from 'react';
import { Platform, StatusBar } from 'react-native';
import * as SystemUI from 'expo-system-ui';

export const useStableStatusBar = (options?: {
  backgroundColor?: string;
  barStyle?: 'light-content' | 'dark-content';
  translucent?: boolean;
}) => {
  useEffect(() => {
    if (Platform.OS !== 'android') return;

    const {
      backgroundColor = '#000000',
      barStyle = 'light-content',
      translucent = false,
    } = options || {};

    // Set status bar properties ONCE at app start
    StatusBar.setBarStyle(barStyle, true);
    StatusBar.setBackgroundColor(backgroundColor, true);
    StatusBar.setTranslucent(translucent);

    // Force Android system UI to respect settings
    SystemUI.setBackgroundColorAsync(backgroundColor).catch(() => {
      // Fallback if edge-to-edge is still enabled
      console.log('[StatusBar] Using fallback mode');
    });

    // Prevent re-renders from affecting status bar
    return () => {
      // Cleanup not needed - status bar is global
    };
  }, []); // Empty dependency array = run once
};
```

## ⚡ **ISSUE #2: SCREEN BLINKING/FLICKERING**

### **Root Cause Analysis**

Blinking is caused by **three common patterns** in Expo apps:

1. **Image loading race conditions**: Grid items re-render when images load
2. **Unstable keys in lists**: Using `index` as key instead of unique IDs
3. **Effect loops**: `useEffect` without proper dependencies triggering re-renders

Your logs show heavy caching activity:
```log
LOG  [Media] Cache hit for c406dabd677e4c51a60d247ce3b2686f.mp4 (437ms)
LOG  [Media] (queue) Copying d53d790fd0fa4857ac49b75103c1b964.mp4 to cache (attempt 1)...
```

### **✅ EXACT FIX: Eliminate Re-render Triggers**

**Step 1: Fix image loading with progressive placeholders**
In your status grid component (likely `src/components/StatusGrid.tsx`):

```typescript
// AFTER (smooth loading):

  placeholder={require('@/assets/images/placeholder-blur.jpg')}
```

**Step 2: Use stable keys in FlatList**
```typescript

  data={statuses}
```

## 🐌 **ISSUE #3: APP SLOWNESS (Heavy Operations)**

### **Root Cause Analysis**

Based on your logs and typical status saver patterns, these are the **performance killers**:

| Operation | Why It's Slow | Impact |
|-----------|--------------|--------|
| **Synchronous file scanning** | Blocks JS thread while reading WhatsApp folder | 2-5s freeze on home load |
| **Loading ALL statuses at once** | 100+ images/videos in memory = RAM pressure | Jank, crashes on low-end devices |
| **Unmemoized selectors** | Re-computing filtered lists on every render | CPU spikes, battery drain |
| **Cache copying on main thread** | `FileSystem.copyAsync` without queuing | UI freezes during save |
| **Video preloading all thumbnails** | Decoding 50+ video thumbnails = GPU overload | Stutter when scrolling |

### **✅ EXACT FIX: Performance Optimization Blueprint**

**Step 1: Lazy-load statuses with virtualization**
Replace your status loading logic with a **paginated, virtualized approach**:

```typescript
// src/hooks/useVirtualizedStatuses.ts
import { useState, useEffect, useCallback } from 'react';
import { WhatsAppStatusFinder } from '@/src/utils/whatsappStatusFinder';

const PAGE_SIZE = 20; // Load 20 items at a time

export const useVirtualizedStatuses = () => {
  const [statuses, setStatuses] = useState<StatusItem[]>([]);
  const [page, setPage] = useState(1);
  const [loading, setLoading] = useState(false);
  const [hasMore, setHasMore] = useState(true);

  const loadMore = useCallback(async () => {
    if (loading || !hasMore) return;
    
    setLoading(true);
    try {
      const allStatuses = await WhatsAppStatusFinder.getAllStatuses();
      const newItems = allStatuses.slice(
        (page - 1) * PAGE_SIZE,
        page * PAGE_SIZE
      );
      
      setStatuses(prev => [...prev, ...newItems]);
      setHasMore(newItems.length === PAGE_SIZE);
      setPage(prev => prev + 1);
    } catch (error) {
      console.error('Failed to load more statuses:', error);
    } finally {
      setLoading(false);
    }
  }, [page, loading, hasMore]);

  // Initial load
  useEffect(() => {
    loadMore();
  }, []);

  return { statuses, loading, hasMore, loadMore };
};
```

**Step 2: Move file I/O to background thread**
Use `expo-file-system` with proper queuing:

```typescript
// src/utils/backgroundFileQueue.ts
class BackgroundFileQueue {
  private queue: Array<() => Promise<void>> = [];
  private processing = false;

  async add(task: () => Promise<void>) {
    this.queue.push(task);
    if (!this.processing) {
      await this.process();
    }
  }

  private async process() {
    if (this.queue.length === 0) {
      this.processing = false;
      return;
    }

    this.processing = true;
    const task = this.queue.shift();
    
    try {
      await task?.();
    } catch (error) {
      console.error('Background task failed:', error);
    }
    
    // Small delay to prevent UI thread starvation
    await new Promise(resolve => setTimeout(resolve, 16)); // ~1 frame
    await this.process();
  }
}

export const fileQueue = new BackgroundFileQueue();
```

Use it for cache operations:
```typescript
// Instead of direct copy:
await FileSystem.copyAsync({ from, to });

// Use queued copy:
await fileQueue.add(async () => {
  await FileSystem.copyAsync({ from, to });
});
```

**Step 5: Add performance monitoring**
Create `src/utils/performanceMonitor.ts`:
```typescript
export const PerformanceMonitor = {
  mark: (label: string) => {
    if (__DEV__) {
      console.log(`⏱️ [PERF] ${label}: ${performance.now()}ms`);
    }
  },
  
  measure: async <T>(label: string, fn: () => Promise<T>): Promise<T> => {
    const start = performance.now();
    const result = await fn();
    const end = performance.now();
    console.log(`⏱️ [PERF] ${label}: ${(end - start).toFixed(2)}ms`);
    return result;
  },
};
```
