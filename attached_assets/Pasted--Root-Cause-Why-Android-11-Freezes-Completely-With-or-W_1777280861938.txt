🔴 SAF Native Module Hang
FileSystem.StorageAccessFramework.readDirectoryAsync() calls Android's DocumentProvider. On OEM skins (MIUI, OneUI, HyperOS), this call can block for 2-8 seconds if the storage indexer is busy. Without a timeout, the JS thread waits indefinitely → app freezes.
Cold launch hangs at 30-60%
🔴 Concurrent Init Starvation
Your _layout.tsx and MediaProvider fire Promise.all([loadSAFUri, loadSavedItems, loadStatusesCache, hydrateTelemetry, AsyncStorage.getItem, adInit]) simultaneously. On Android 11+, SQLite (AsyncStorage) + SAF IPC + Ad SDK init compete for I/O → JS thread blocks → UI unresponsive.
Entire app stuck on splash
🔴 Unbounded Memory/GC Pauses
expo-image cache + FlashList render window + background thumbnail queues allocate 150-300MB on first paint. Android's ART Garbage Collector pauses the main thread for 500ms-2s to reclaim memory → feels like a complete freeze.
Swipe/tap unresponsive, white screen
Bottom Line: The freeze is not a bug in your logic. It's main thread starvation + native SAF hangs + uncontrolled concurrent I/O on Android 11+. The fix requires hard timeouts, serialized init phases, I/O throttling, and memory capping.
